## 明细

### 🔴 RED：`Kun.Saga`

**现象**：当 MSBuild 在 `Kun.Saga` 上收到 `-p:PublishAot=true` 时，该属性会向下传递到所有被引用的项目。因为 `Kun.Saga.csproj` 直接引用了 `Kun.EntityFrameworkCore`，EF Core 模块被迫在 AOT 模式下重编，命中如下错误（摘录）：

```
src/Kun.EntityFrameworkCore/EfRepository.cs(29,18):
  error IL2091: 'TEntity' generic argument does not satisfy 'DynamicallyAccessedMemberTypes.PublicConstructors'…
  in 'Microsoft.EntityFrameworkCore.DbContext.Set<TEntity>()'

src/Kun.EntityFrameworkCore/InProcessDomainEventDispatcher.cs(47,37):
  error IL2060: Call to 'System.Reflection.MethodInfo.MakeGenericMethod(params Type[])' can not be statically analyzed
  error IL3050: Using member '…MakeGenericMethod…' which has 'RequiresDynamicCodeAttribute'

src/Kun.EntityFrameworkCore/IntegrationEventOutboxAccumulator.cs(44,23):
  error IL2026: Using member 'System.Text.Json.JsonSerializer.Serialize<TValue>(TValue, JsonSerializerOptions)'
```

**根因**：`Kun.Saga/Persistence/Ef/*.cs`（`EfSagaInstanceStore`、`SagaInstanceConfiguration`、`SagaStepQueueEntryConfiguration`、`KunSagaDbContextExtensions`）把 EF 持久化与编排器混在同一程序集里，违反了 Kun 既定的 "EF 与 AOT 候选模块必须物理分离" 约定（对照 `Kun.MultiTenancy` ↔ `Kun.MultiTenancy.EntityFrameworkCore` / `Kun.Audit` ↔ `Kun.Audit.EntityFrameworkCore` 已经落地的模式）。

**短期修复（本次 PR 完成）**：把 `Kun.Saga` 降级为 `IsAotCandidate=false`，让当前的 CI AOT loop 实事求是（它本来就没把 Saga 放进循环）。

**长期修复（跟进 issue）**：抽出 `Kun.Saga.EntityFrameworkCore`：
- `Kun.Saga`（纯抽象，AOT 候选）：`ISaga`、`ISagaStep`、`SagaContext`、`SagaState`、`SagaInstance`（POCO 无 EF 配置）、`ISagaInstanceStore`、`SagaOrchestrator`、`SagaTimeoutDetector`、`SagaStepExecutor`、`SagaRegistry`、`KunSagaServiceCollectionExtensions`
- `Kun.Saga.EntityFrameworkCore`（非 AOT）：`EfSagaInstanceStore`、`SagaInstanceConfiguration`、`SagaStepQueueEntryConfiguration`、`KunSagaDbContextExtensions`

该 split 是破坏性修改（消费者的 `AddKunSaga()` 需要额外 `.UseEntityFrameworkCore()` 调用），与 `neuroagent-csharp` 的集成节奏耦合，故放到 Phase 2 的 `P2-KN-Saga-EF-Split` 里跟进。

### 🟡 YELLOW：`Kun.Dapper`

**现象**：`Kun.Dapper.csproj` 没有 `<IsAotCandidate>`。从代码上它是 thin wrapper（`KunConnectionFactory`、分页扩展），查询读侧依赖 `Dapper.AOT` 源生成器实现 AOT。目前默认缺省 = 非 AOT，与 `Directory.Build.props` 的 `Condition="'$(IsAotCandidate)' == 'true'"` 契约没有矛盾，但**语义不清**。

**修复**：显式设置 `<IsAotCandidate>false</IsAotCandidate>`。真正的 AOT 测试在每个具体 Query handler 里做（由 `Dapper.AOT` source generator 保证），而非在 `Kun.Dapper` 自身。

### 🟢 其余 18 AOT 候选模块

均干净通过 ILC。以 `Kun.Mediator` 与 `Kun.Sandbox` 两个有代表性的模块为样本：

- `Kun.Mediator`：`Handler` 注册通过 source generator 在编译期生成 `FrozenDictionary<Type, RequestHandlerBase>`，零反射。
- `Kun.Sandbox`：`SupervisorSandboxProvider` 通过 `HttpClient` + `KunJsonContext` 走 `JsonTypeInfo`，`InMemorySandboxProvider` / `E2BCloudSandboxProvider` 零反射。

## AOT 相关 MSBuild 属性集中化情况（对应 S3）

`Directory.Build.props` 现有集中化（已合规，无需再改）：

```xml
<PropertyGroup Label="AOT Compatibility" Condition="'$(IsAotCandidate)' == 'true'">
    <IsAotCompatible>true</IsAotCompatible>
    <IsTrimmable>true</IsTrimmable>
    <EnableTrimAnalyzer>true</EnableTrimAnalyzer>
    <EnableAotAnalyzer>true</EnableAotAnalyzer>

```

全仓扫描显示**仅 `samples/Kun.Sample.Minimal/Kun.Sample.Minimal.csproj` 本地声明 `<PublishAot>true</PublishAot>`**，但这是合法的：`Sample.Minimal` 是可执行入口，需在自身 csproj 上显式启用 publish-time 的 native 编译（库项目不应声明 `PublishAot`，靠 analyzer 即可）。

S3 的具体动作变为：
1. 保持 Directory.Build.props 现状。
2. 补一段显式 `EnableDynamicLoading` 说明（默认即 `false`，但文档化避免后续某模块误启用）。
3. 在 `Directory.Build.props` 里新增兜底：当 `IsAotCandidate=false` 时不要开 AOT 分析器（当前 Condition 已经如此）。
