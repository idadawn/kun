# 租户查询过滤器修复前后微基准

本记录对应 `2026.10.12-2` 的 DbContext 绑定修复，沿用 [2026-04-23 基线](baseline-2026-04-23.md) 中的 `MultiTenancyQueryFilterBenchmarks`。修复前使用 `4f334c1a1ad411b2735d247a0b0993d6e83cc51e` 的原始代码；修复后使用同日修复候选及迁移后的基准调用入口。

两版在同一台 Apple M5 Max 上串行运行，期间没有 `dotnet test`。环境为 macOS 26.6.2、.NET SDK 10.0.300、.NET Runtime 10.0.8 Arm64、BenchmarkDotNet 0.14.0。使用既有 ShortRun：一次启动、三轮预热、三轮测量；每个 RowCount 在两个租户各准备对应行数。

| 方法 | 每租户行数 | 修复前均值 µs | 修复后均值 µs | 观察到的均值变化 | 修复前分配 B | 修复后分配 B |
|---|---:|---:|---:|---:|---:|---:|
| 手动 Where 对照 | 100 | 14.099 | 13.873 | -1.60% | 53192 | 53192 |
| Kun 查询过滤器 | 100 | 13.173 | 13.734 | +4.26% | 50536 | 50728 |
| 手动 Where 对照 | 1000 | 114.679 | 110.780 | -3.40% | 470800 | 470800 |
| Kun 查询过滤器 | 1000 | 116.436 | 122.132 | +4.89% | 468144 | 468336 |

过滤器路径每次查询增加 192 B 分配；对照路径分配不变。三次测量的均值观察值增加约 4%–5%，但修复前过滤器样本的置信区间较宽，不能据此认定稳定的耗时回归或提升。原始分布、标准差与误差区间保留在 [修复前 JSON](tenant-filter-2026-10-12-before.json) 和 [修复后 JSON](tenant-filter-2026-10-12-after.json)。

这是 EF InMemory 的表达式执行与分配微基准，不代表 PostgreSQL 查询吞吐、生产服务容量或目标部署硬件表现。修复的正确性由真实 PostgreSQL 租户隔离与共享模型回归单独验证；本地微基准不代替 CI 基线。

复现命令（分别在对应源码目录执行，并用不同产物目录保存）：

```bash
dotnet run -c Release --project benchmarks/Kun.Benchmarks -- --filter '*MultiTenancyQueryFilterBenchmarks*' --artifacts <结果目录>
```
